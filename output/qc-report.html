The edge reality — what the numbers say

Against the closing spread, the model loses money at every threshold

ATS win rate by model edge · 2,277 games, 2017–2025 · break-even at −110 is 52.4%

52.4% break-even

Not only does it never clear the bar — it trends down as the model's claimed edge grows (48.6% at 3+ points). A big model-vs-market gap is the model being wrong, not finding value. This is the single most important truth in the whole system, and it's why the honest thesis was never "beat the spread."

CLVThe one real signal — closing-line value — is genuine but sub-vig

The market does move toward our side after we'd have bet: +0.46 pts on spreads, +0.43 on totals, both wildly significant (p<1e-22), and it scales with edge. That's a real anticipatory signal. But graded at the opening price you'd actually get, spreads still win only 51.2–51.6% — below the 52.4% you need. Half a point of CLV isn't enough to overcome the juice.

The lone flicker: totals bet at the opener hit 54.5% at edge ≥3 — but that's not statistically above break-even (p=0.12), it's unstable across seasons, and it vanishes entirely by close (50%). Plausible, unproven, and it depends on actually getting the opening number.

PropsThe prop program has no proven edge — and a fabricated headline stat

There is no historical prop backtest anywhere — no posted book lines in the data, no hit-rate or ROI against the market. Props are only validated on "beats a naive baseline" (MAE), which says nothing about beating the book. The advertised prop_brier = 0.051 is mathematically impossible: the floor implied by its own calibration table is 0.227. The projections look well-calibrated, but good calibration is not edge — treat the whole calibration.json headline as untrustworthy until rebuilt.

Critical — bugs in the picks being published now

✓ All four resolved

Every bug below has been fixed, tested (53/53), and committed, and the board republished. They're kept here for the record. The pick-run is now a single committed entry point (src/run_board.py), so the fixes reproduce every week.

C1Game-script is backwards on every published pick

A sign error reads spread_line with the wrong convention, so favorites are scored as underdogs and vice-versa. On the live board a favorite's WR gets "pass-heavy script helps" and a road dog's RB gets "game script helps the run" — both inverted. It corrupts the Game Flow slider (fires on 10/10 picks) and the implied-points feeding anytime-TD.

Fix Flip the team-spread assignment in board_factors._game_ctx (dog = positive). One line.

C2The board can publish "Under" when the model itself says "Over"

The "skew-neutralization" step subtracts the median model-vs-market edge per market, which forces a ~50/50 over/under split by construction and re-anchors the model to the market. Players the model likes for the over at 56–58% get flipped and published as unders. It's erasing the genuine directional edges, not cleaning skew.

Fix Drop the re-centering, or at minimum never let it publish a side that contradicts the raw model probability.

C3The thinnest-data picks are topping the board

The Desk Score is documented to "peak at 8% edge and penalize beyond 11%" — but the code is a straight line that rewards ever-bigger edges up to the cap. So the #1 and #3 picks are a thin-data WR (not even in the fantasy ADP file) with 16–17% "edges" — exactly the stale-model blowups the design says to suppress. The per-play investigation verdict is computed but then ignored by the ranker.

Fix Implement the documented hump curve, and actually consume the investigate multiplier instead of a dead hard-coded penalty.

C4The "calibrated" TD model ships raw, uncalibrated numbers

A calibration function is defined and then never called — the anytime-TD board publishes the raw Poisson probability while the docstring calls it "the calibrated model." Every TD p_model, implied prob, and edge is off.

Fix Call p_calibrated() in the TD pricing (one line), or drop the "calibrated" claim.

+Two more that mislead the board

Missing fantasy ADP is treated as proof of a "small role," which auto-confirms unders and auto-suspects overs on exactly the thin-data players we should distrust. And three different name-matchers across files mean stars (James Cook, Kenneth Walker, Travis Etienne) silently miss their ADP/role joins — so their factor sliders run on defaults.

Fix One shared name normalizer; treat "no ADP" as unknown, not as a small role.

Real vs. narrated — the autonomous layer

ReproducibilityThe board can't be regenerated for Week 2

The published ranked_board.json was assembled by an inline one-off script that was never committed. The ranker's only committed caller runs on synthetic test data; the other scripts only re-read the existing file. There is no single committed weekly pick-run (odds → build → publish → grade). This is the most consequential gap: the product cannot be reproduced.

"Gets smarter weekly"The self-update engine re-tests one parameter

It checks a single variable (road-dog), bumps a version number, and isn't even wired to the real 74-parameter registry. The impressive changelog (v1/v2/v3, "67 params") was hand-authored, not produced by the engine. The "add / cut / reweight by significance" promise doesn't exist yet.

"Daily research bot"A 3-example harness plus a relabeled simulation

The tests themselves are real (real data, real p-values), but there is no scheduler and no agent inventing hypotheses. The "30-day sprint" was one simulation run with a faked calendar. Genuine analysis, mis-narrated as an autonomous system.

AutomationX / Discord / Whop / public record — zero code

No integration anywhere, no scheduler, no public graded-record page. The "graded in public vs the close" trust premise — the whole reason a picks brand earns followers — does not exist yet.
